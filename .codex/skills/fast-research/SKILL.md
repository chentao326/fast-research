# 快速调研法（Fast Research）

基于老蒋巨靠谱的"快速调研法"方法论，AI 代理执行五步调研流程。

**核心理念**：问题先行，以搜养收。AI 做 dirty work，人做 high-level thinking。

---

## 触发条件

当用户提出以下请求时自动激活：
- "调研 XX" "帮我研究 XX" "快速了解 XX" "分析 XX 行业" "/research"

---

## 前置步骤：检测搜索能力

执行调研前，必须先评估当前环境可用的搜索工具，按优先级检测：

### 搜索能力检测链

```
检测顺序：
1. web_search 工具（最优先，最快）
2. 浏览器自动化（Playwright/agent-browser skill）
3. exec_command + curl 搜索脚本
4. 上述均不可用 → 告知用户，降级为"问题框架输出模式"
```

**检测方法**：

**优先级 1——`web_search`**：
直接尝试调用。如果返回 "unsupported" 或错误，跳到下一级。

**优先级 2——浏览器自动化**：
检查是否有 Playwright（node_repl 已加载）或 agent-browser skill。有则用浏览器打开搜索引擎（Bing cn.bing.com 或 Google）获取结果。

**优先级 3——`exec_command` + 本地搜索脚本**：
使用项目中的 `search.sh` 脚本，通过 curl 访问搜索引擎。
注意：此方式可能被搜索引擎反爬拦截，如果连续失败则跳过。

**优先级 4——纯离线模式**：
所有搜索方式不可用时，基于 AI 已有知识库回答问题，但必须在报告中明确标注"未做实时搜索验证"。

---

## 搜索的 Agent 辅助策略（重要）

当调研涉及多个并行问题时，**在步骤 2 和步骤 3 应使用 sub-agent 并行搜索**：

### 何时用 Agent

| 场景 | 策略 |
|------|------|
| 步骤 2 框架搭建 | 可以将不同维度（市场规模、产业链、主要玩家）分给 2-3 个 explorer agent 并行搜索 |
| 步骤 3 深度搜索 | 将 3-5 个具体问题分给多个 worker/explorer agent 并行深挖 |
| 调研对象很大 | 按子话题拆分，每个 agent 负责一个子话题 |
| 快速模式 | 通常不需要 agent，串行即可 |

### Agent 使用模板

```
对 explorer agent 的指令格式：

"请帮我搜索关于【具体问题】的信息，需要：
1. 直接答案（1-3 句话）
2. 支持数据/案例
3. 如有争议观点也列出
返回格式：Markdown 列表"

对 worker agent 的指令格式：

"请帮我整理【子话题】的调研结果，生成结构化笔记，
包含：定义、关键数据、主要玩家、趋势判断"
```

### Agent 使用原则

- Agent 并行搜索，主线程等待汇总
- 每个 agent 只负责一个明确的子任务
- Agent 返回后，主线程做整合和交叉验证
- 如果环境不支持 agent（如无 multi_agent 工具），则串行搜索

## 执行流程

### 步骤 0：初始化（必做）

```
🎯 开始调研：【调研对象】
⏱️  模式：【快速 30min / 标准 2h / 深度 半天】
📋 流程：问题先行 → 二手信息 → 深度搜索 → 整理输出 → 回归初心

在开始之前，确认：
1. 调研目的是什么？（面试准备/工作报告/个人兴趣/其他）
2. 有没有特别想搞清楚的具体问题？
```

如果用户没有具体问题，AI 自行生成问题清单供确认。

---

### 步骤 1：问题先行（~5 分钟）

AI 自行生成 **5-8 个结构化问题**，分为三档，呈现给用户确认。

**问题生成模板**：

```markdown
## 📋 调研问题清单

### 基础层（事实信息）
1. [市场规模/用户量] 
2. [产业链/上下游结构]
3. [主要参与者及各自定位]

### 进阶层（分析判断）
4. [竞争格局/核心壁垒]
5. [商业模式/盈利方式]
6. [关键趋势/发展方向]

### 高级层（深层洞察）
7. [这个行业为什么存在？满足什么需求？]
8. [核心竞争力是什么？会不会被颠覆？]
```

**原则**：
- 先自己生成，不要一上来就问用户"你想了解什么"
- 高级层的问题必须有——这是人类对 AI 仅剩的优势
- 用户确认/调整后进入步骤 2

---

### 步骤 2：二手信息汇总（建立框架）

**目的**：不求深入，求**广度**——为步骤 3 的深度搜索打基础。

**搜索策略**：
- 2-3 轮搜索，覆盖：行业概览、主要玩家、近期动态
- 如果环境支持 agent 并行，将不同维度分给 2-3 个 explorer agent
- 用可用搜索工具执行（见"搜索能力检测链"）

**输出模板**：

```markdown
## 📚 二手信息框架

### 基本信息
- **定义**：[一句话说清楚]
- **规模**：[规模/用户量]
- **主要参与者**：[Top 5-10 及定位]
- **产业链**：[上下游关系]

### 关键概念
- [概念1]：[一句话解释]
- [概念2]：[一句话解释]

### 近期动态
- [重要事件 1]
- [重要事件 2]

### ⚠️ 信息缺口
以下问题当前信息不足，需步骤 3 深挖：
- [缺口1]
- [缺口2]
```

**原则**：
- 标注"信息缺口"是关键——这驱动步骤 3
- 如果搜索覆盖不足，主动告知用户

---

### 步骤 3：深度搜索（定向深挖）

**目的**：针对缺口和尚未回答的问题，逐条深挖。

**搜索策略**：
- 每条问题至少 2 次搜索，不同关键词、不同角度
- 支持 agent 并行：将问题分给多个 explorer agent
- 对每个回答追问"为什么"和"怎么做到的"至少一层

**追问技巧**（当 AI 回答太宽泛时）：
> "你别说那么多。把其中最重要的两点给我揪出来。"
> "不要说套话。如果只让你说一个最关键的数字和一个最反直觉的发现，是什么？"

**输出模板**：

```markdown
## 🔍 深度搜索结果

### 问题 A：[具体问题]
**直接答案**：[1-3 句话]
**支持证据**：[数据/案例]
**争议**（如有）：[不同观点]
**追问一层**：[深挖发现]

### 问题 B：[具体问题]
（同上结构）
```

---

### 步骤 4：整理归纳（结构化输出）

将所有成果整合为完整调研报告。

**报告模板**：

```markdown
# 【调研对象】调研报告
> 调研时间：[日期] ｜ 耗时：[xx 分钟] ｜ 方法：快速调研法

## 一、一句话总结
[最核心认知]

## 二、行业概览
### 2.1 定义与范围
### 2.2 市场规模
### 2.3 产业链结构

## 三、竞争格局
### 3.1 主要玩家与分类
### 3.2 竞争要素

## 四、关键洞察
### 4.1 核心竞争力
### 4.2 趋势判断
### 4.3 风险与挑战
### 4.4 争议话题

## 五、调研局限
[诚实标注无法通过快速调研获得的信息及建议获取方式]

## 六、进一步学习建议
- 📖 书单 / 🎥 内容 / 👤 建议找谁聊
```

---

### 步骤 5：回归初心

回到步骤 1 的问题清单，逐条检查：

```markdown
## ✅ 问题回答对照

| 问题 | 状态 | 核心结论 |
|------|------|---------|
| [问题1] | ✅ | [一句话结论] |
| [问题2] | ⚠️ 部分 | [已知 + 未知] |
| [问题8] | ❌ 无法回答 | [原因 + 建议获取方式] |
```

---

## 三种模式参数

| 参数 | 快速 ⚡ | 标准 📋 | 深度 🔬 |
|------|---------|---------|---------|
| 搜索轮次 | 2-3 轮 | 5-8 轮 | 10+ 轮 |
| Agent 并行 | 不用 | 可选 | 推荐 |
| 问题数量 | 3 个核心 | 5-8 个 | 8-12 个 |
| 交叉验证 | 不做 | 2 次 | 3-4 次 |
| 报告深度 | 精简版 | 完整版 | 完整+书单+争议分析 |

---


### 文件输出约定（强制）

步骤 4 的报告**必须写入文件**，不能只显示在对话中。

- 输出路径：`{workspace}/research_output/{调研对象}-调研报告.md`
- 文件名规则：去除特殊字符，用 `-` 连接，示例：`AI-Agent行业调研报告.md`
- 如果 `research_output/` 不存在，自动创建
- 报告写入完成后，告知用户文件路径

步骤 1 的问题清单也建议写入 `research_output/` 目录，方便对照。


---

## 核心原则

1. **问题先行**：先列问题，再搜索。不漫无目的浏览。
2. **以搜养收**：搜索中的新发现反过来优化问题清单。
3. **AI 做 dirty work**：搜索、整理、格式化。
4. **人做 high-level thinking**：判断、洞察、取舍留给用户。
5. **标注局限**：诚实标注无法获得的信息，不假装全能。
6. **追问至少一层**：对每个关键发现追问"为什么"。
7. **搜索能力自适应**：检测可用工具，按降级链选择搜索方式。
8. **Agent 辅助并行**：多问题/大范围时用 sub-agent 并行搜索，主线程汇总。
